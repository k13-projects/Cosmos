## Summary

One NEXT press now reads exactly as Kazim asked: the plate on screen leaves to the right, and a
tenth of a second later the next plate flies in from the left, sails a little past the middle,
comes back, and rocks itself still. It is a hand-built damped curve, not a framer spring, because
a spring cannot do both halves of that ask at once.

**Why not `type: "spring"`.** A spring's overshoot is a fixed fraction of its travel. To arrive
from 60% of the stage away and only overshoot 5%, the damping ratio has to be about 0.62, and at
0.62 the second swing is 0.4% of the stage, sub-pixel, so there is no "little shake" left. Lower
the damping to get three visible swings and the first overshoot grows to 25-40% of the stage,
which is snappy and cartoonish, the opposite of the brief. So travel and wobble are decoupled: one
damped cosine whose amplitude envelope changes gear the instant it first crosses the centre.

```
x(t) = -dir * A(t) * cos(phi(t))          x in % of stage width, dir = +1 for next

arrival, t <= 0.34s     A = 60 * exp(-2.485 * t/0.34)      phi = pi * t/0.34
settle,  t >  0.34s     A = 5 * exp(-(t-0.34)/0.1671)      phi = pi * (1 + (t-0.34)/0.145)
```

Sampled at 60 Hz into 64 keyframes and handed to `motion` as a linear keyframe track, so the curve
that ships is the curve written above. It lives in `flightTrack()` at the top of the component.

### The recorded values

| Constant | Value | What it sets |
|---|---|---|
| `TRAVEL` | 60% of stage width | where the plate starts and where it exits |
| `ARRIVE` | 0.34 s | first half-cycle, off-stage to the first peak |
| `OVERSHOOT` | 5% | envelope amplitude at the top of the arc |
| `HALF` | 0.145 s | half-period of the settle wobble |
| `DECAY` | 0.42 | amplitude left after each half-period |
| `ENTER_MS` | 1050 ms | total flight |
| `ENTER_DELAY` | 0.10 s | the handoff pause, so it reads out-then-in, not swap |
| `EXIT_MS` | 450 ms, `cubic-bezier(0.42, 0, 1, 1)` | the outgoing plate, accelerating away |
| exit opacity | 360 ms linear | plate; the name goes faster, 200 ms |
| enter opacity | 240 ms linear, 100 ms delay | plate |
| name rise | `y: [18, 0]`, 550 ms `cubic-bezier(0.22, 1, 0.36, 1)`, 220 ms delay | house premium ease-out, `--ease-brand` |
| name opacity | 460 ms `--ease-brand`, 260 ms delay | settles as the wobble dies |
| `FADE_MS` | 250 ms | reduced motion cross-fade |
| `LOCK_MS` | 480 ms | minimum gap between committed slide changes |

Derived: `k1 = ln(60/5) = 2.485`, `tau = -0.145 / ln(0.42) = 0.1671 s`.

The overshoot measures 6.65% rather than the 5% envelope constant because the envelope is still
decaying when the cosine reaches its peak, so the true maximum lands slightly before phase pi. The
5% is the amplitude at the top of the arc; 6.65% is what the eye sees.

Swing peaks at 1280, incoming plate: **+6.65% (+59 px) at 378 ms**, then -2.15% (-19 px) at 578 ms,
+0.92% (+8 px) at 728 ms, -0.38% (-3 px) at 877 ms, +0.16% (+1 px) at 1011 ms. Under 1 px from
1052 ms, dead centre from 1152 ms. **Three swings you can see, two you cannot, gone in 1.05 s.**

Outgoing plate at 1280: last visible frame 361 ms at +355 px, lands at +535 px (+60%) at 453 ms. It
is invisible well before it could reach the arrow. Name handoff: old name gone at 203 ms, new name

**Previous** is the exact mirror, verified: 50 ms after a PREV press the leaving plate is at -1.06%

### The other proofs

- **Rapid clicks.** 5 clicks in 1004 ms from slide 1: ends on **slide 1** (five steps round a ring
  of five, correct), **at most 2 plates ever visible at once**, exactly **1 plate visible at rest**,
  live region reads "Spicy Jam, 1 of 5". No doubled plates, no gap, no stuck state. Clicks inside
  the 480 ms lock are queued, not dropped, and collapse into one hop, so the carousel never runs a
  five second backlog.
- **Reduced motion** (CDP `Emulation.setEmulatedMedia`, `prefers-reduced-motion: reduce`, confirmed
  by `matchMedia` returning true): **max plate travel 0 px, max name rise 0 px**, incoming fades
  0 to 1 over 240 ms, outgoing fades out by 341 ms. Cross-fade only, no travel, no spring, no
  keyframe track built at all.
- **No horizontal scroll:** `scrollWidth == innerWidth` at all four widths (375/375, 768/768,
  1280/1280, 1920/1920).
- **Clipping:** the only clipping ancestor between the plate and the page is the section itself
  (`overflow-x: clip`), at every width. Nothing clips mid-stage; the plate is cut only at the
  section edge, which is the intended behaviour.
- **Console:** clean, no errors and no messages at all.
- **Performance:** transform and opacity only, no layout during the flight. The stage is sized by
  aspect ratio so the section height never moves. `will-change: transform, opacity` is set only on
  the two slides in flight and drops back to `auto` on the other three.
- **Keyboard, focus, DOM contract:** ArrowLeft/ArrowRight drive the same queue, focus stays on the
  carousel, `aria-roledescription="carousel"`, the five `slide` groups, `aria-current` dots, the
  polite live region and the seam tab are all unchanged.

## Risks

1. **`motion`'s accelerated opacity flashes one frame at the end, on this version.** Measured on
   the shipped build: the leaving plate jumped back to 100% opacity for one frame at 362 ms, the
   arriving plate blinked to 0% at 346 ms, the arriving name at 771 ms. `motion` hands a lone
   opacity tween to the browser's own animation engine, and cancelling that at the end paints one
   frame at the element's base value before the final value lands. Transform never does it, because
   the keyframe track keeps it on motion's own clock. **Fix shipped:** x and y stay with `motion`,
   opacity moved to plain CSS transitions. Verified: zero single-frame spikes on all four tracks.
   Worth a Lessons entry, since it will bite any future `motion` component on this project.
2. **The site-wide reduced-motion reset silently kills any component cross-fade.** `globals.css`
   forces `transition-duration: 0.01ms !important` on `*`, so the 0.25 s cross-fade the brief asks
   for came out as a hard cut. **Fix shipped:** a narrow `.carousel-xfade` opt-out inside the same
   media block, on the plate and the name only. Nothing travels, nothing springs; only the fade is
   restored. If James disagrees with the exception, delete the rule and the class and the carousel
   falls back to an instant swap under reduced motion, with nothing else affected.
3. Under reduced motion the outgoing plate starts its fade about 90 ms in rather than immediately,
   an inherited transition delay, so the cross-fade runs 341 ms end to end rather than 250. No
   travel, no spring, and visually a clean cross-fade. Left as is; chasing it is not worth another
   build cycle.
4. `motion` is now actually imported (it was a dependency nobody used). First Load JS for `/` is
   159 kB, shared chunks 103 kB, unchanged from the previous build within rounding.
5. Not tested: real touch swipe on hardware. The swipe handler is unchanged and still picks its
   direction from the sign of the drag, and it now feeds the same queue as everything else, but it
   was exercised only through synthetic events.
