  character generation via Meshy/Tripo, confirmed via `ps aux` and console noise leaking across a

  measurement script of mine initially suggested the mobile wheel's `overflow-hidden` clip was not
  actually clipping content (plates measuring up to 200px past the belt's edge) — this was
  `getBoundingClientRect()` ignoring the ancestor clip, the exact Lesson 31 trap, in a script I
  wrote fresh this session, not a copy of the earlier one. Caught it by drawing a real reference
  line and zooming into the actual painted pixels (`wheel-clip-boundary-zoom.png`) before reporting
  anything: the clip is correct, nothing paints past it.
- **`prefers-reduced-motion` was not re-driven live this round.** My fix only changes when a
  caption's opacity is triggered (focus vs. always-on), not the rotation or reduced-motion gating
  logic in `globals.css`, which I never opened. Trusting engineering's own verified numbers
  (ring pinned at 0deg, drag still works with no momentum) rather than re-deriving them, since nothing
  in this fix touches that code path. Worth a quick re-check in a future pass if that logic
  ever changes.
- **Desktop hover tooltip (mouse) was not independently re-driven with a live CDP hover this
  round** — the automated hover tool timed out waiting for the plate's own subtle float animation

  redundant `lg:opacity-0` into the existing base `opacity-0`, no selector or logic change) — low
  risk, but flagging honestly rather than claiming a live re-test I didn't get to complete.
  `lg:group-hover:opacity-100` is unchanged and present in the compiled CSS.
