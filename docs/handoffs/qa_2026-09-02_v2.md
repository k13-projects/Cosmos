## Risks
- **The wheel's 15px clearance at 1440 and above.** The lowest plate's deepest reach clears the
  "Fresh always" icon row by 107px at 1024, 54px at 1280, 30px at 1366 and **15px** at 1440, 1536 and
  1920. Positive everywhere, never a collision, but 15px is thin and the plate's drop shadow is not
  counted in that box. Any edit to the About copy length, to Values' `lg:pt-36`, or to `--wheel-r`
  re-opens it. This is the first number to re-measure after any copy change, and it is a tighter
  constraint than Natalia's handoff implies.
- **The nav logo over cream is carried entirely by its drop shadow.** Yellow on `#FFF2E1` has almost
  no contrast of its own. It reads today and it is the mechanism Kazim chose over a ground, so it
  stands, but softening that shadow would break it. Over a yellow display headline mid-scroll it is
  the same story and it still reads.
- **Touch was emulated, not felt.** `Input.dispatchTouchEvent` is not on the browse CDP allowlist, so
  the tap path was exercised with a real pointer click. It shares the `:focus-visible` behaviour that
  produced QA-v2-02, but a phone in a hand is still untested.
- **`sips -Z 2048` in `scripts/build-assets.sh`** still starves the two portrait photo bands of
  width. Unchanged from my v1 report, still open, still not a release blocker.
- **Horizon is unlicensed.** The tooltip pill widths and the footer handle widths are both sized
  against real strings in Archivo. When the real face lands, both need re-measuring, along with every
  display headline.
- **The AVIF to JPEG fallback flattens the cutout's alpha** for a browser that accepts neither AVIF
  nor WebP. Cosmetic, and only on browsers below the modern support floor.
- **Untested surfaces are listed in full in the report**: real hardware, screen readers, Safari and
  Firefox, the live preview domain, performance, external destinations. None is assumed passing.

## Evolution
My first wheel sweep returned zero collisions at every width and I nearly filed it. It was a false
pass: `scroll-behavior: smooth` on `html` plus Lenis meant a 0.3s settle after `window.scrollTo`
measured the previous position, so all 72 samples read the same frame, and `--wheel-rot` sat at a
flat 32deg. The tell was in the output the whole time and I only caught it because the rotation
number looked too constant. The fix that stuck is not a longer sleep, it is counting **distinct**
rotation values per sweep and printing them, so a sweep that did not move is visibly not a sweep.
Same lesson as my v1 pass and the second time it has cost me a cycle: a clean result on a check that
has never once failed is evidence the check is broken, not evidence the code is good. The harness
now proves the mechanism moved before it reports what it saw.

Second one worth keeping: `document.querySelector("footer")` is not the site footer on this page.
The review cards each use a `<footer>` element, so the first match is a Google review card, and my
first footer sweep returned empty columns and empty socials at all four widths, which read exactly
like a pass. Scope to `footer#contact`.
