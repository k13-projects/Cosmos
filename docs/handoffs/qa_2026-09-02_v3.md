## Risks
- **Natalia's "Fresh always" wheel-clearance numbers (84/100/165px) were a false near-miss.**
  Her table compared plate-left-edge to text-left-edge as a straight 1D subtraction. At 1024,
  1280 and 1366 the wheel and "Fresh always" never share a screen row at all (700px+ apart
  vertically), so there's no real proximity to measure. Re-checked with true 2D rectangle
  overlap: zero collisions at all six widths, and where rows do intersect (1440+) the real
  clearance is 418-658px, not 15-165px. Not a defect, just a corrected number - worth carrying
  into her sicil/taste notes so the next wheel-geometry change is checked against the right
  method.
- **Hover pause on the plate wheel wasn't captured end-to-end.** This harness's `hover` command
  times out against a continuously-moving target (correctly so - the plates never stop moving
  until paused). A direct attempt did freeze rotation exactly once, and the tooltip/pause CSS
  is the identical class list for hover and focus (`group-hover:opacity-100` /
  `group-focus-visible:opacity-100`), and focus passed clean end-to-end (pause, pull-into-view,
  tooltip, resume). Treating focus as the verified proxy; a clean hover capture needs either a
  different tool or a human on a real trackpad.
- **Image-upscale false positive, investigated and closed.** `hero.webp`, `band-phone.webp` and
  `monkey-fries.png` flagged as upscaled by the automated sweep (`img.naturalWidth` reading
  smaller than the CSS box). Verified via `curl` and an in-page `fetch()` +
  `createImageBitmap()` of the identical URL: both decode to the true, correct source size at
  every width checked. This is a quirk of `img.naturalWidth` under this harness's CDP viewport
  override, not a real image-serving defect. Flagging so a future sweep doesn't re-chase it as
  new.

## Evolution
The wheel-clearance check in Natalia's engineering handoff used a 1D horizontal-only comparison
for the "Fresh always" distance, which manufactured a 15px "near miss" out of two elements that
are never even in the same screen row below 1440px width. The fix that stuck: for any clearance
claim between a moving element and a fixed one, check whether their vertical ranges actually
intersect before subtracting x-coordinates - a horizontal-only gap between things at different
heights on the page is not a real measurement of anything. Worth folding into the fitcheck
methodology for any future rotating/orbiting element.
