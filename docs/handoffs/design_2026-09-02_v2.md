# Design handoff, location marks (Valentina, 2026-09-02, v2)

## Status      PASS

## Summary
Five monochrome venue marks, one per Locations card, sized for the bottom-right corner Kazim
asked for (War Room environment-card precedent, mirrored to the opposite corner, silhouettes
instead of vendor logos). Silhouette treatment won over the duotone-photo alternative for all
five venues, including Global Fork, so the set stays one coherent family rather than splitting
into two techniques.

Each mark is a hand-built flat silhouette (no photo tracing, no third-party image embedded),
drawn from the client's own location photos and the sister-project renders/logos:
- **Windmill (Carlsbad)**: the actual onion-dome windmill tower and its crossed sail, with a
  small gabled roof at its foot, referencing THG's own `windmill.png` wordmark art and
  `Cosmos Assets/Location Photos/Windmill Foof Hall.jpg`.
- **Oceanside**: the storefront's scalloped shake-shingle awning and its triangular trellis roof,
  from `cosmos-burger-oceanside.webp` (old-site archive). Provisional, see Risks.
- **Miramar (San Clemente)**: the mission tower's pyramidal tile roof and finial over the arched
  porch, from `Location Photos/Miramar Food Hall.png` and `Miramar/website/images/story/
  2026-outside.jpg`.
- **Global Fork (Little Italy)**: the entrance's stone pilasters and flat marquee canopy, from
  `Location Photos/Global Fork 2.jpg` and `GlobalFork/public/photos/storefront.jpg`. The building
  itself (a generic mixed-use residential tower) is not a distinctive silhouette, so the mark
  abstracts the real, photographed entrance instead of the whole tower. Still a silhouette, still
  drawn from the actual building, so the set stays one technique.
- **Station 8 (UCSD)**: the public market's swept cantilever canopy rising into the residential
  tower behind it, from `STATION8/public/renders/station8-exterior.png` (the building is not open
  yet, so this is the only source there is).

All five sit on a shared 200x200 grid, flat solid fill, no strokes, bottom-anchored, so they read
as one system at a glance despite five different buildings.

Proof mock at `docs/handoffs/screens/design_2026-09-02_v2/location-marks-mock.png` composites all
five onto a faithful re-build of the real card (`components/Locations.tsx`'s own tokens: cream
`#FFF2E1`, radius 40, purple `#751080` heading, magenta-ink `#9C1BAA` eyebrow/Directions). A
close-up detail crop is at `location-marks-detail.png`. A 375px mobile check confirms the mark
still reads at the rail's `78vw` mobile card width.

**Contrast, quoted**: purple heading text (`#751080`) on plain cream (`#FFF2E1`) is 8.89:1. Where
the mark's own 18%-opacity purple tints the cream underneath it, the composite background is
approximately `#E6C9D0`, and text on *that* would still measure 6.36:1, both comfortably past
WCAG AA (4.5:1) for body text. This only matters if a future layout change moves copy over the
mark; today the mark sits in the card's empty bottom-right quadrant, never under the address,
hours, phone, Order pill or Directions link at any of the breakpoints checked (1280, 768, 375).

## Integration spec, for Natalia

Add one `<img>` (or inlined `<svg>`, either is fine) per card, absolutely positioned inside the
existing `<li>`'s card `<div>` (which is already `position: relative` via the flex column, so add
`relative` if it is not already implicit):

```tsx
<img
  src={`/locations/${l.markFile}.svg`}
  alt=""
  aria-hidden="true"
  className="pointer-events-none absolute bottom-0 right-0 aspect-square w-[20%] opacity-[0.18]"
/>
```

- **Position**: `absolute`, `bottom: 0`, `right: 0` inside the card. It should sit flush into the
  card's own rounded corner, not inset from it; the SVGs are already bottom/right-weighted inside
  their viewBox so this reads correctly against the `rounded-[40px]` card without extra clipping.
- **Size**: `width: 20%` of the card, `aspect-ratio: 1 / 1` for height. At the desktop card
  (`min(33.3vw, 480px)`, aspect 443/289) that is roughly 88-96px square. Scales naturally at
  every breakpoint since it is percentage-based, confirmed legible at the 375px `78vw` mobile
  card in the mock above.
- **Opacity**: `0.18` baked into the class, not the SVG. This is the one number Kazim gave a
  range for (15-20%, "80 to 85 percent transparency"); 18% is the picked value, expose it as a
  single Tailwind arbitrary value or a CSS variable (`--mark-opacity: .18`) so it is a one-line
  tune, not a per-file edit. The color itself IS baked into each SVG (`fill="#751080"`, the base
  brand purple, not a tint) since the brief asked to bake the tint but leave opacity to the
  component.
- **`pointer-events: none`** and **`aria-hidden="true"`**, plus an empty `alt=""`, since this is
  pure decoration standing in for the venue, not information; a screen reader user already gets
  the venue name from the card's own `<h3>`.
- **z-index**: none needed. It should paint after the card background but the existing content
  (eyebrow, heading, address, hours, phone, Order/Directions) is laid out in normal flow above it
  in DOM order, and none of it overlaps the bottom-right 20% square at any breakpoint tested, so
  no stacking context fight to manage.
- **Hover variant**: none. Kazim didn't ask for one and the mark is a static watermark, not an
  interactive element; adding motion here would compete with the card's own hover lift.
- **Per-venue file map** (add a `markFile` field to each `Location` in `lib/content.ts`, or just
  switch on `l.id`, whichever fits the existing shape better):

  | `location.id`     | file                          |
  |--------------------|-------------------------------|
  | `carlsbad`         | `public/locations/windmill.svg`     |
  | `oceanside`        | `public/locations/oceanside.svg`    |
  | `san-clemente`     | `public/locations/miramar.svg`      |
  | `little-italy`     | `public/locations/global-fork.svg`  |
  | `ucsd`             | `public/locations/station-8.svg`    |

## v2 update, 2026-09-02 (Valentina)

James's read on v1: the five silhouettes are too plain to carry a client card on their own, and
Kazim asked to be surprised, so this update builds the real comparison rather than asserting the
pick. Three techniques, same five venues, same corner, same 20% of card, same 18% opacity (the
middle of Kazim's 15-20% ask), so the only variable across rows is the mark technique itself.

**A. Silhouette.** Unchanged from v1, the hand-drawn flat vector icons at `public/locations/*.svg`.

**B. Duotone stamp.** The real venue photo, cropped to the building, luminance-mapped from cream
`#FFF2E1` (highlights) to brand purple `#751080` (shadows), with a soft rounded-corner alpha fade
baked in so it melts into the card rather than sitting as a hard rectangle. Built with PIL and
numpy: grayscale luminance drives both the color lerp and the alpha (darker pixels are both more
purple and more opaque), gamma 0.8 to lift midtones, then a Gaussian-blurred rounded-rect mask
knocks the alpha to zero toward the crop's own edges. Assets at `public/locations/duotone/*.png`.

**C. Detailed trace.** The same crop, OpenCV Canny edge detection (per-venue thresholds, roughly
40/120) at a working resolution of 800px on the long edge for all five so the line weight reads
as one family, then a 2x2 dilate to unify stroke thickness and a light Gaussian blur on the alpha
channel so lines anti-alias instead of looking jagged. Keeps windows, roof lines, the windmill's
sail, the Miramar gable's actual "Food Hall" lettering, and Station 8's canopy structure, all as
line work rather than flat fill. Assets at `public/locations/trace/*.png`.

**Sources used**, all real photography or the client's own render, nothing invented:
- Windmill: `Cosmos Assets/Location Photos/Windmill Foof Hall.jpg`
- Miramar: `Cosmos Assets/Location Photos/Miramar Food Hall.png`
- Global Fork: `Cosmos Assets/Location Photos/Global Fork 2.jpg` (the exterior shot, not the
  interior one also in that folder)
- Station 8: `STATION8/public/renders/station8-exterior.png` (the venue is not open, so this
  construction-era render is the only building photography that exists anywhere)
- Oceanside: `Cosmos Assets/OLD SITE ARCHIVE/media/cosmos-burger-oceanside.webp`. The brief named
  the `burger-oceanside-near-me-*.webp` files as the ones to pick from, but all ten of those
  (`-1` through `-10`, plus the unnumbered one) are byte-identical duplicates of the same loaded
  fries product shot, an old-site scraper artifact, not ten different photos. None of them show
  the storefront. `cosmos-burger-oceanside.webp`, already used for row A, is the only real
  exterior anywhere in the archive, so it carries into B and C as well.

**The proof mock**: `docs/handoffs/screens/design_2026-09-02_v2/location-marks-mock-v2.png`.
Rows A, B and C are all at the true deployed size and opacity, so the comparison is honest, not
staged. Below them is a fourth strip, clearly labelled "reference only, not the shipped opacity",
showing B and C at 55% so the actual linework and duotone detail is visible on its own terms.

**The honest finding**: at 18% opacity and 20% of a 443x289 card, row A reads clearly at a glance
on every one of the five, because it is a purpose-drawn icon that is solid ink across its whole
silhouette. Rows B and C are photographic derivatives: most of each crop is empty sky, glass or
wall, so even though every pixel in all three rows shares the same 18% ceiling, B and C's *average*
ink density across the mark is roughly half to a third of A's (measured: duotone crops average
~46-51% internal alpha before the 18% multiply, versus A's solid fill; trace crops are 25-50% of
their crop actually touched by a line at all). The result: B and C look closer to a faint watermark
texture than a readable shape at the spec'd size and opacity, especially Miramar and Station 8
where the interesting detail (the tower, the canopy) is a smaller fraction of the crop. The
reference strip exists precisely so this isn't mistaken for "B and C have no detail", they have
plenty, it just doesn't survive the 18% ceiling as legibly as a flat icon does.

**Contrast, re-checked for B and C.** Purple text `#751080` on plain cream `#FFF2E1` is 8.89:1 (as
in v1). The worst case for any row, where a single pixel sits at the full internal alpha (255) a
photo or icon can reach, composited at the shared 18% container opacity, is the same for A, B and
C: composite `≈ #E6C9D0`, text contrast 6.38:1. That's the ceiling, not the typical case. Sampling
the actual generated assets: duotone crops average roughly 46-51% internal alpha, which at 18%
works out to about 8-9% effective opacity and a text contrast around 7.5:1; trace crops, measured
only over the pixels an edge actually touches, average roughly 55-70% internal alpha, about
10-11% effective opacity and roughly 7.3:1 text contrast. All three rows, worst case and typical
case alike, clear WCAG AA (4.5:1) with real margin; B and C in fact read as slightly higher
contrast than A in the typical case, precisely because they carry less average ink.

## Risks, v2 addendum
- **B's file sizes are heavier than A's.** The five duotone PNGs run roughly 580KB-870KB each
  (photographic gradients don't compress like flat vector fills). Fine for this comparison; if B
  ships, run them through a PNG optimizer (pngquant or similar) before they go to production,
  they'll shrink considerably without a visible quality loss at 18% opacity.
- **B and C both use `object-fit: contain` anchored bottom-right in the mock**, not `cover`,
  because the five crops don't share one aspect ratio (Global Fork's crop is a tall 450x800
  sliver, Station 8's is a wide 800x466 strip) and forcing a uniform square crop would either
  squash the buildings or cut off the parts that make each one recognizable. If B or C ships, this
  is the one integration detail that differs from A's spec above, everything else (position, size,
  opacity, `pointer-events`, `aria-hidden`) carries over unchanged.
- Canny thresholds in C were tuned per venue by eye (roughly 35-50 low / 110-140 high) rather than
  one fixed number, because a single threshold either buried Miramar's tile roof lines or turned
  Station 8's window grid to noise. If a sixth location is ever added, expect to tune its threshold
  too rather than reusing one of the five as-is.
