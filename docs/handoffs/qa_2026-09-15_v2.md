## Risks

- **This machine was under heavy, unrelated load for the full run** (`load averages: 10.28 10.16
  9.07`, `ps aux` showing multiple concurrent Chrome/headless-shell instances from other sessions
  plus a separate Postgres-grants script running). This produced one real, reproducible tooling
  issue worth recording: emulating a viewport with the `mobile`/`touch` flags together
  (`isMobile:true, hasTouch:true`) forces a full page reload to apply the new user-agent/touch
  capabilities, and that reload never completed within several successive waits (up to ~30s,
  `document.readyState` stuck at `"interactive"`, mobile plate images never reaching `.complete`)
  on two separate tabs in a row. Confirmed the *server* was not the bottleneck (`curl` against the
  same image URL round-tripped in 0.28s both times) — this was browser/tab-side congestion, not a
  server or product issue. **Worked around, not avoided**: for every mobile-width measurement I used
  `emulate` with only `width`/`height`/`devicePixelRatio` (no `mobile`/`touch` flags), which applies
  instantly with no reload — CSS breakpoints only care about the pixel width, not the device-type
  flags, and the touch/drag gesture tests were separately exercised with synthetic
  `PointerEvent{pointerType:"touch"}`, matching every prior round's own method (real touch hardware
  has never been available in this environment). Worth flagging forward: an `emulate` call carrying
  `mobile`/`touch` on this specific site, under load, is a known trap for the next session — prefer
  width-only emulation for layout work and synthetic pointer events for gesture work, as I did here.
- **Server left running** at `localhost:9157`, rebuilt fresh by me this session (current working
  tree, no code changes since). Kill with `pkill -f next-server` if the next agent doesn't need it.
- **`prefers-reduced-motion` re-driven only for the mobile wheel's rotation/drag**, not for every
  other animated element on the page (this round's changes never touched any other motion code
  path, so re-driving the rest would not have told me anything new).
